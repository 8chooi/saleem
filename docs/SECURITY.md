## 1. مبادئ الأمان الأساسية

1. **ولي الأمر هو صاحب الحساب الرئيسي** — الطفل لا يملك حساباً مستقلاً
2. **الأمان على الخادم دائماً** — لا ثقة في الواجهة
3. **RLS على كل بيانات المستخدمين** — Supabase Row Level Security
4. **لا أسرار في كود الواجهة** — env variables على الخادم فقط
5. **أقل الصلاحيات** — كل دور يرى ما يحتاجه فقط

---

## 2. حماية الأطفال (إلزامي من اليوم الأول)

### ما هو ممنوع
- ❌ حسابات أطفال مستقلة بدون ولي أمر
- ❌ محادثات مفتوحة بين الأطفال
- ❌ جمع معلومات شخصية غير ضرورية (اسم كامل، صورة وجه، مدرسة)
- ❌ نشر بيانات طفل لأي طرف
- ❌ مشاركة بيانات طفل مع مدرسة بدون موافقة ولي الأمر
- ❌ إعلانات سلوكية للأطفال
- ❌ روابط خارجية غير موثوقة في تجربة الطفل
- ❌ أي chatbot مفتوح يتواصل مع أطفال

### ما هو مطلوب
- ✅ ربط كل طفل بولي أمر واحد على الأقل
- ✅ ولي الأمر يوافق على انضمام الطفل لفصل مدرسي
- ✅ آلية لحذف الحساب وجميع البيانات
- ✅ سياسة خصوصية واضحة بالعربية
- ✅ تحقق من الصلاحيات على الخادم وقاعدة البيانات

## 3. بنية الصلاحيات

### الأدوار
```
super_admin  — كل الصلاحيات
admin        — إدارة المحتوى والمستخدمين
content_author — إنشاء المحتوى (يحتاج مراجعة)
content_reviewer — مراجعة واعتماد المحتوى
teacher      — فصله وطلابه فقط
parent       — أطفاله المرتبطين به فقط
```

### RLS مثال
```sql
-- parent يرى أطفاله فقط
CREATE POLICY "parent_see_own_children" ON child_profiles
FOR SELECT USING (
  id IN (
    SELECT child_id FROM parent_child_links
    WHERE parent_id = auth.uid()
  )
);
```

## 4. المصادقة

- **Provider:** Supabase Auth
- **Methods:** Email/Password (أساسي), Google OAuth (مستقبلي)
- **Sessions:** JWT مع refresh tokens
- **Password:** Supabase يطبق معايير قوية
- **Route Protection:** Middleware في Next.js
- **Mobile:** AsyncStorage آمن عبر Expo SecureStore

---

## 5. البيانات والخصوصية

### ما نجمعه
- Email ولي الأمر (للحساب والتواصل)
- اسم الطفل (عرض فقط، يمكن أن يكون اسماً مستعاراً)
- سنة الميلاد التقريبية (لتحديد المرحلة)
- تقدم التعلم والنقاط

### ما لا نجمعه
- صور وجوه الأطفال (الأفاتار رسوم متحركة فقط)
- اسم المدرسة الحقيقي إلا عند ربط الحساب بمدرسة
- الموقع الجغرافي الدقيق
- بيانات الجهاز التفصيلية

### حذف البيانات
- ولي الأمر يستطيع حذف ملف طفل
- ولي الأمر يستطيع حذف حسابه الكامل مع كل البيانات
- الحذف نهائي ومكتمل (Soft delete للأرشفة، Hard delete عند الطلب)

## 6. أمان الكود

### قواعد صارمة
```
✅ Server-side validation لكل input
✅ Parameterized queries (Supabase يتولاها)
✅ CSRF protection (Next.js يتولاها)
✅ XSS prevention (React يتولاها + sanitization)
✅ Rate limiting على API routes
✅ لا console.log للبيانات الحساسة
✅ لا secrets في git
❌ لا SUPABASE_SERVICE_ROLE_KEY في الواجهة
❌ لا eval() أو dangerouslySetInnerHTML بدون sanitization
```

## 7. الامتثال القانوني

> **تحذير:** لا ندّعي امتثالاً قانونياً كاملاً حتى تتم مراجعة مختص.

### المراجع للمستقبل
- قانون حماية البيانات المصري
- COPPA (للمستقبل — إذا توسعنا لأمريكا)
- GDPR (للمستقبل — إذا توسعنا لأوروبا)

### الحد الأدنى الحالي
- سياسة خصوصية واضحة
- موافقة ولي الأمر على إنشاء حساب الطفل
- آلية حذف البيانات
- لا بيانات حساسة غير ضرورية
